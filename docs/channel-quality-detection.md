# 渠道题目降智检测

在「分组健康」顶部打开「降智检测配置」。配置仅属于当前用户、当前连接站点，其下已开启的分组共同使用。默认全局和分组均关闭。

1. 选择检测模型、推理强度和判断方式，编辑题目、答案、匹配方式及耗时阈值。
2. 在「检测配置」设置正常间隔、异常复测间隔、连续异常和恢复次数、并发及超时；启用并保存。
3. 打开左侧需要检测的分组的「降智检测」开关。后台会自动检测其中渠道，关闭浏览器也继续执行。

配置方式参考 Qerkai-sub2api 的题目检测。支持导入它的 JSON 题库与题目调度参数；不导入模型一致性或自动处理配置。导入后默认关闭，需确认并保存。

每轮每渠道执行一道已启用题目。标准答案允许纯答案或唯一的 `FINAL_ANSWER=` 行，也支持关键词和 Go 正则表达式。内容和耗时可单独或共同判断，耗时必须严格小于题目阈值，计时包含完整响应读取。有效答题后按题库顺序轮换；失败请求保留题目位置。

绿色表示本题通过，红色表示有效回答未满足规则，黄色表示检测请求失败。通过率仅统计有效答题。连续异常达到阈值才显示「降智」，连续通过达到恢复阈值才解除；网络、认证、限流、空响应和截断响应不累计答错次数。鼠标停在色块上可查看题目、实际答案、判断结果、耗时及时间。记录条最多显示当前配置的最近 100 次检测。

检测会使用渠道自己的上游凭据发送模型请求，复用现有渠道凭据解析能力；无法取得凭据或地址时显示检测失败，不伪造答题结果。OpenAI 使用 Responses，端点不存在时兼容 Chat Completions；Anthropic 和 Gemini 使用各自协议。只接受完整的最终文本回答，不允许工具调用。相同渠道被多个已开启分组覆盖时只检测一次。

结果独立存入 `connection_health_quality_*` 表。此功能不调用健康策略状态机、调权、暂停账号、切组或任何远端处理。修改配置会产生新版本，旧版本历史不参与新判定；保存相同配置保留原版本与进度。保存结果时再次检查配置版本和分组开关，防止在途旧任务在关闭或修改后写入有效结果。每站点使用数据库租约防止多实例重复检测，站点并发可配置为 1～32，进程总并发不超过 32。

验证覆盖答案匹配、完成响应识别、计时、错误分类、轮换与连续次数、配置校验、作用域隔离、共享渠道去重、并发控制、配置变更及关闭后的旧结果拒绝。PostgreSQL 集成测试验证持久化、历史裁剪和无浏览器请求下的连续后台检测；页面通过隔离模拟接口验证，不开启真实渠道。
